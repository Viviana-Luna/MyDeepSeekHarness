# 问题报告：输入区读数条在窄窗口整体消失

状态：第一至六节问题已按第八节修复；标签边缘与窄屏项目入口问题的修复见第九节。
涉及文件与行号以报告编写时的工作区为准，修复后行号已有变化。

## 一、现象

窗口宽度 1169 逻辑像素（截图 2338×308 设备像素 @2x）时，输入卡片下方的会话读数条
（上下文占用环 + 百分比、输出速度、累计 Token）**整条不存在**：卡片下沿之后直接是浮岛底色，
没有任何胶囊、图标或文字。同一会话在窗口宽度 1298 逻辑像素（截图 2596×204）下，
同一读数条正常显示在卡片正下方，约 207 逻辑像素宽、居中于卡片。

读数条本身只有约 207 逻辑像素宽，而卡片在这两个宽度下分别有 642 / 774 逻辑像素，
空间完全够用，因此这不像是空间不足导致的降级。

## 二、触发规则（代码位置）

1. `src/renderer/src/pages/workspace/components/mainpanel/chat-mainpanel/index.tsx:82`

   ```tsx
   const showReadings = !compact && snapshot.informationCollapsed
   ```

   读数条不渲染时，`ComposerStatus` 整体不挂载（同文件 86 行传给 `<Composer>`），
   所以不只是隐藏，而是组件与它的面板入口一起消失。

2. `src/renderer/src/hooks/useCompactInformation.ts`

   ```ts
   window.matchMedia('(max-width: 1268px)')
   ```

   窗口宽度 ≤ 1268 逻辑像素即视为 `compact`。

3. `src/renderer/src/styles/layout.css:359` 同一条断点还会
   `.info-island { display: none }`，并隐藏右栏分隔条与缩放角。

因此实际规则是：

- 窗口 ≤ 1268 ⇒ `compact` ⇒ 读数条不渲染（与卡片实际可用宽度无关）；
- 右栏展开 ⇒ 读数条同样不渲染（与窗口宽度无关，该条件用于避免与右栏重复，见第四节）；
- 窗口 ≤ 1080 时，`ComposerStatus.module.css` 里"只隐藏读数文字、保留图标"的
  `@media (max-width: 1080px)` 永远遇不到已渲染的读数条——它在窗口维度上是失效规则。

## 三、实测数据

两张截图均为整窗宽度、@2x；用 Electron `nativeImage` 逐像素扫描（脚本 `/tmp/wishreport/measure2.js`，
结果 `/tmp/wishreport/measure2.txt`）。

| 项目 | 截图 1（窄） | 截图 2（宽） |
| --- | --- | --- |
| 窗口宽度 | 1169 逻辑像素 | 1298 逻辑像素 |
| 输入卡片 | x 424–1065，宽 642 | x 424–1198，宽 774 |
| 读数条 | 不存在 | 存在，x 710–917，宽约 207，居中于卡片 |
| 卡片下沿之后（中心列） | 恒定浮岛底色 25–26（无任何内容像素） | 读数条图标与文字（亮度 90 以上） |
| 工具行 | 仅图标 | 图标 + 文字（工作区内修改 / 普通 / Skill） |

判读依据：读数条行高 24 逻辑像素，其图标与文字在卡片下沿约 10–38 设备像素处产生亮像素。
截图 1 在卡片下沿（y=284）之后到图像结束（y=307）始终是 25–26 的浮岛底色，
即该区域没有任何读数内容，可以排除"截图裁掉了读数条"的可能。

## 四、影响

1. **读数不可见**：上下文占用百分比、输出速度、累计 Token 在 ≤1268 的窗口下完全看不到。
2. **明细面板无法打开**：读数条的胶囊同时是"上下文 / 耗时与速度 / Token 使用 / 本轮待办"
   四个面板的唯一入口（`ComposerStatus.tsx` 内的 `AnchoredPanel`），读数条不渲染时这些明细也一起消失。
3. **替代入口同时关闭**：右栏（`rightpanel/chat-rightpanel/index.tsx`）确实展示同样的四项读数
   （上下文、Token、耗时与速度、本轮待办），但它在 ≤1268 的布局断点下是 `display: none`，
   因此窄窗口下四项读数都没有第二处可以查看。

## 五、复现步骤

1. 打开一个已有会话，使输入卡片下方的读数条出现（窗口宽于 1268）。
2. 把窗口宽度从 1300 缩到 1200，跨过 1268 断点：读数条整条消失；再放大回 1300：恢复。
3. 保持宽窗口（例如 1440），展开右侧信息栏：读数条也整条消失（这一步与宽度无关，是设计意图）。
4. 窗口 ≤1080 时观察不到"仅图标"的读数条形态，可直接确认那条降级规则没有生效机会。

## 六、判断与建议（待你确认，尚未改代码）

1. `1268px` 这个断点的本意是"右栏能否并排"（`mainpanel/index.tsx` 用它决定右栏与窗口按钮的位置），
   与"读数条能否放下"不是同一件事。读数条在卡片内部、宽度只有约 207 逻辑像素，
   用窗口断点决定它的存亡属于信号错配。
2. 建议把读数条的显示判据改为**输入区容器宽度**（`.composer-dock` / 插槽宽度），
   或至少把阈值下调到卡片实际放不下读数条的位置。
3. 建议保留"右栏展开时不重复显示"的规则：右栏已经包含同样的四项读数，重复显示没有价值。
4. 建议把现成的三档降级改成容器查询：宽 → 完整胶囊（图标 + 文字）；
   中 → 仅图标（把 `@media (max-width: 1080px)` 改为 `@container` 形式，让它真正生效）；
   窄 → 整条隐藏。

## 七、附录：另一处已知显示异常（会话标签左端重影）

同一轮排查中定位到的独立问题，细节与证据在对话记录与 `/tmp/wishglass/`：

- 现象：当前标签页（选中态）左端圆角外多出一条柔光弧，与标签自身 1px 描边叠成"双层边"，
  右端只有很轻的内移，两端不对称。
- 原因：`.session-tab-track::before { inset: -3px }` 让浏览器计算 `objectBoundingBox`
  用的盒子比液体玻璃引擎使用的材质盒宽 6px，导致透镜区域被横向拉伸并整体左移约 3px，
  烘焙在位移图里的边缘高光因此落在标签描边之外。
- 已在本机复现工程验证的修复方向：让材质盒覆盖轨道突起
  （`.session-tab-material { inset: -10px -3px; padding-inline: 3px }`），
  并把 `useSessionTabGlass.ts` 中透镜位置改为按材质盒换算。

## 八、修复记录

按第六节建议实施（三档降级 + 右栏去重）：

1. 显示判据从窗口宽度改为输入区容器宽度：`ChatComposer` 用新增的
   `useElementWidthAtLeast` hook 测 `.composer-dock` 实际宽度，
   低于 `READINGS_DOCK_MIN_WIDTH`（180px）才整条卸载；完整读数约 207px、
   仅图标形态约 116px，阈值留出居中余量。
2. “只隐藏读数文字、保留图标”改按读数行自身宽度触发：`ComposerStatus.module.css`
   的 `.readings` 声明为 `composer-readings` 查询容器，原先在窗口维度上永远
   遇不到已渲染读数条的 `@media (max-width: 1080px)` 改为
   `@container composer-readings (max-width: 280px)`。
3. 右栏去重规则保留但修正语义：只在右栏真正可见（宽窗口且未收起）时隐藏读数条；
   窄窗口下右栏被布局隐藏，读数条照常显示，不再与右栏同时消失。
4. 文档同步：README、docs/renderer.md 与 `useCompactInformation` 注释改为描述新规则。

整条隐藏仍走组件卸载而非 CSS 隐藏：`.app-shell:has(.composer-dock [data-composer-readings])`
按读数条 DOM 是否存在推导卡片高度上限与右下角把手位置，CSS 隐藏会留下空白读数行。

## 九、标签边缘与窄屏项目入口修复

标签材质盒横向扩展 3px 并保留等量内边距，覆盖底轨伪元素的完整绘制范围；透镜中心从标签容器坐标换算到材质盒坐标，使滤镜与外沿对齐。位移图分辨率取不小于标签设备像素宽度的偶数，至少保留 512，避免宽标签把固定大小的位图横向放大。

页面宽度不超过 780px 时，项目选择器使用限定于左侧浮岛的隐藏规则，避免被后加载的组件 `display: grid` 覆盖；沿用窄栏仅保留搜索入口的布局。Electron 验收增加 725px 场景，等待侧栏动画结束后检查项目入口隐藏、搜索入口未裁切，并恢复原窗口最小尺寸。

## 十、玻璃纹理性能回归修复

提高横向分辨率后，玻璃库仍生成正方形位移图。1092px 宽、26px 高的标签按 2 倍设备像素生成 2184×2184 纹理，造成绘制掉帧和尺寸变化时的主线程长任务。

`patches/liquid-glass-web-react@0.1.1.patch` 让引擎按透镜长宽比例生成矩形纹理，短边保留四倍采样用于圆弧抗锯齿。相同标签改为 2184×208，保留横向清晰度，像素数减少约 90%。公开计算函数与直接生成接口的默认正方形行为保持不变，面板分隔条不受影响。

隔离 Electron 使用同一份真实会话历史与终端面板做前后对照；历史仅临时投影，不写回用户日志。按 2 倍设备像素生成纹理时，标签切换的 95% 帧间隔从 33.3ms 降至 16.8ms，终端右栏连续拖动从 33.4ms 降至 16.7ms；单个宽标签展开时的最大帧间隔从 166.6ms 降至 16.8ms，位移图计算与编码从 75ms 降至 11.2ms。后台对照用于确认改动效果，不代替真实窗口的人工体验验收。
