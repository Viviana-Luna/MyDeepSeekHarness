# Git AI 提交

AI 提交位于「变更」左栏的「提交消息」标题右侧。点击入口只展开准备卡；确认提供方、模型与范围并点击「开始分析」后，才发送所选差异。手动提交和快捷键仍然只提交暂存区，AI 流程不清空手动消息草稿。

## 审阅与恢复

- 默认选择已暂存、未暂存和未跟踪的非空类别，不读取 Git 忽略文件。准备卡下方的常规列表继续用于查看 Diff。
- 方案只按文件版本分组，不自动应用模型生成的补丁。点击方案文件，中央 Diff 显示 HEAD 到此次实际待提交版本的差异。
- 同文件同时有暂存和未暂存内容时，选择两个范围会得到一个整文件版本，必须明确确认或暂不提交。仅选暂存范围时只提交索引版本，未暂存内容保持不变；仅选工作区而该文件已有暂存内容时拒绝自动处理。
- 消息、顺序、归属、合并和暂不提交在左栏调整。混杂功能或无法可靠归类的文件进入暂不提交；把它移回批次后仍需明确确认整文件处理。
- 按序提交前还有一次原位确认。每批成功后保留提交；hook 失败或并发变化会停止后续批次，不 reset、不 stash、不 push。
- 工作区、HEAD、索引或 Git 配置变化后，旧方案不能继续执行，必须重新分析和审阅。仅修复 hook、所涉内容未变化时，可复核后重试剩余批次。

## 后台边界

renderer 复用受限 `projects.call`，主进程验证来源 frame、已登记项目、操作、字段和值，再转到 `mydshWorkspace/call`。后台 Cordis 服务持有快照；renderer 只能提交标识、消息与确认，不能提交路径、命令或补丁。模型调用显式使用 `tools: []`，异常不把模型请求正文或凭据写入普通日志。

快照包含完整真实索引字节、HEAD、分支身份、有效 Git 配置摘要、所选文件内容和工作区摘要。仓库外索引只用于协调和冲突检测，不发送模型。执行每一批时：

1. 复核基线，独占真实 `index.lock` 与 `HEAD.lock`。
2. 准备候选索引与原索引副本，复核两者中本批之外的条目均未变化。随后使用独立的候选 HEAD 和索引，共享原仓库对象库、配置、hooks 与签名设置，运行正常 `git commit`。有效配置与原仓库不同时拒绝，不能悄悄关闭签名。
3. 检查候选树和父提交与审阅版本完全一致，再次复核真实仓库。hook 修改候选内容或工作区时，不发布候选到用户分支。
4. 通过旧对象标识比较更新明确分支，然后原子安装已核验的索引副本。不改写工作区文件。

候选阶段 hooks 看到独立的 detached HEAD；依赖原分支身份或条件配置的 hooks / 仓库需手动提交。未发布候选的对象仍由 Git 管理，不会撤销前面已发布的批次。如果引用发布结果无法确认或索引协调失败，保留恢复所需的索引锁文件并要求人工检查，不强行覆盖或重试。

## 当前限制与生命周期

重命名（包括跨项目移动）、同路径删除后重建、二进制、非 UTF-8、符号链接、子模块、空内容或权限变化、特殊/稀疏/分裂索引、冲突及合并/变基过程要求手动处理。项目边界两侧同时出现新增与删除时，即使 Git 未识别为重命名，也保守要求手动处理。使用内容过滤或 CR 换行的工作区文件可先手动暂存，再仅分析暂存范围。尚无首个提交或 detached HEAD 的仓库不执行 AI 提交。

分析最多 200 个项目内变更。用于安全提交的本地完整文件快照独立限为 16 MiB，采样时累计检查；发给模型的差异输入限为 256 KiB，不会因为大文件只有几行修改就把完整文件计入模型输入。超限不会截断或静默省略文件，而是停止并显示具体预算；可取消部分分析类别，或手动暂存部分文件后仅分析暂存区。

模型返回的方案文本限为 64 KiB（UTF-8），流式增量与权威完整块不重复计量。推理摘要、协议字段和 ChatGPT 私有回放密文不属于方案，AI 提交接收器不保存这些内容，也不读取或序列化私有回放。流式事件另限为 131072 个，内容块另限为 4096 个；超限或异常结束仍中止分析并释放模型流，不截断方案。

错误提示区分 Git 读取、输入超限、模型请求、方案校验和工作区复核。已知业务校验显示安全文案，提供方或子进程的原始异常正文、凭据和 cause 不透传。分析失败后撤销请求，退出或重试不会再次报窗口归属错误。

单次分析 90 秒，执行任务 10 分钟，每个 Git 子进程 90 秒。方案保留 30 分钟。取消、项目切换、页面离开和运行时退出会中止任务并丢弃迟到结果；Git 使用现有受管子进程服务，等待进程树退出后才释放锁及临时目录。引用发布到索引协调这一小段不接受取消，以免留下反向暂存。

隔离仓库测试位于 `tests/git-ai-*.spec.*`，左栏组件测试位于 `tests/renderer-git-ai.spec.tsx`。真实 Electron 准备卡与滚动验收并入 `pnpm run verify`；单元测试和构建不等同于真实界面验收，也不代表真实提供方或签名密钥的端到端验证。
