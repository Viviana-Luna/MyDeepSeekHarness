# 从 DSH 导入数据

MyDSH 的用户数据位于 `~/.mydsh/data`，业务设置唯一保存在 `~/.mydsh/config/settings.yaml`。导入沿用 DSH 的会话 ID、父子会话关系与存储格式，不与原 DSH 共用可写日志。

先停止来源 DSH，在 MyDSH 导入界面选择原数据目录，检查预览中的会话、项目、设置类别、凭据名称和问题报告，再提交。提交期间 MyDSH Runtime 必须停止；成功后由桌面宿主重新启动 Runtime，导入器本身不恢复任务、不调用模型、不执行工具。

## 支持的内容

- 会话目录为 `sessions/<项目>/<会话>/session[.vN].jsonl[.zstd]`，选择最高版本的完整 generation。实际版本与事件校验复用应用附带的 Session 格式目录。
- JSONL 与 Zstandard 均可读取，目标统一使用 Zstandard 多帧编码。每个物理记录独立一帧，头帧保持一行。未知格式、损坏记录、尾部不完整或混合编码会阻止提交，不会截断原日志。
- 项目来自 `storages/workspace.json` 的 v2 格式，保留项目顺序、会话顺序和归档集合。相同项目路径合并；项目 ID 冲突时记录映射，Session ID 冲突则拒绝覆盖。
- 复制会话实际引用的 `attachments/v1` 内容，核对内容摘要；缺失或损坏附件列为警告。
- 导入受支持的模型、Agent 预设、权限、压缩、Skills、目标及子 Agent 设置类别。MyDSH 已有的类别保持现有值；未知类别明确列出。内联密钥不进入普通设置。
- 凭据必须单独选择。预览只显示 `ref:` 或 `record:` 名称；主进程将选择的值交给 DSH 本地凭据文件提供方，不复制 `.credentials.yaml`，不把明文回传给 Agent。

profile、插件、运行任务状态、锁文件和其他存储域不复制。单个输入或解压后的日志上限为 256 MiB，超过时明确报告，保留原文件。

## 提交与恢复

预览记录来源摘要。提交前重新读取来源，暂存完成后再次核对；来源变化时要求重新预览。提交在 `~/.mydsh/.import-*` 中分别构建完整候选 `data` 与 `config`，保留 MyDSH 已有的配置、凭据文件与扩展启用索引。源 `settings.yaml` 合并到候选 `config/settings.yaml`，活动 `data` 中不创建第二份配置。

两个目录的重命名无法构成单次文件系统原子操作。因此导入停止 Runtime 与配置写入者，先记录两份旧目录是否存在，再切换候选目录，最后以原子重命名写入成功标记。标记前失败会同时恢复旧数据和旧配置；标记后只清理旧副本。在这个提交窗口内收到取消，也必须先完成联合提交或完整恢复，不能把一新一旧的目录交给运行核心。

正常失败或取消清理暂存目录。进程意外退出后，桌面宿主在安装器创建数据目录、启动 Runtime 或写入配置前调用 `recoverDshImport`。恢复记录损坏或旧副本无法恢复时，保留暂存目录并阻止启动，不把恢复失败误报为成功。恢复和提交持有同一个应用单实例锁，主进程还会拒绝重叠的导入操作。

来源和目标必须是不重叠的绝对路径，导入器不跟随符号链接。原 DSH 数据只读，所有来源与 Session 映射记录在 MyDSH 的 `.mydsh-imports.json` 中。重复导入跳过已导入的相同会话；若原会话后来变化，则报告冲突，不覆盖 MyDSH 中的会话或重新编号。

## 从 MyDSH 导出会话日志

在会话的“轨迹”页点击“导出日志”，选择 ZIP 保存位置。MyDSH 直接读取自己的数据目录，收集目标会话及头行中可识别的全部子会话，只保存每份日志的最高代际；不访问 HTTP 服务、不导出锁文件，也不打包附件、项目配置、设置或凭据文件。日志正文可能包含消息和工具原始输入输出，分享前应检查敏感信息。

ZIP 保留 `sessions/<项目>/<会话>/<日志>` 布局。会话已停止且日志完整时，解压目录可以作为导入预览的来源；附件未随包交付，相关引用可能显示缺失警告。导出不逐条校验或修复日志，运行中的会话仅按读取时取得的字节保存，尾部可能不完整，不能保证可重新导入。需要可恢复的副本时，请先停止相关会话再导出并检查导入预览。

单份 ZIP 上限为 2 GiB，导出超时为 15 分钟。取消或失败会关闭文件流并删除临时文件，已有目标文件只在成功后替换；目标或子会话 ID 重复时拒绝任意选择来源。

## 开发接口

`previewDshImport` 返回元信息、摘要和问题列表；`commitDshImport` 接收用户已预览的 `expectedFingerprint`。二者都需要注入已安装核心的 `sessionFormatCatalog`，以及可选的实际支持设置类别列表。

`importDshCredentials` 仅供主进程使用，接受选中名称与 `writeCredential` 写入回调。它不应注册为普通 Agent 工具或可读取密钥的 RPC 方法。凭据写入不是数据目录事务的一部分，失败时停止后续凭据写入，已完成项由凭据存储自己的替换策略处理。
